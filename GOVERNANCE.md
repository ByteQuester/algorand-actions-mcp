# Project Governance

Algorand MCP Workers operates as an open-source project with transparent governance, community participation, and clear decision-making processes. This document outlines how the project is organized, how decisions are made, and how contributors can participate in governance.

- **📚 Education**: Comprehensive documentation and learning resources

## 🗳️ Decision Making Process

### 🔄 Consensus-Based Decision Making

We strive for consensus on all decisions, using the following process:

1. **Proposal**: Anyone can propose changes through GitHub Issues or Discussions
2. **Discussion**: Community discussion and feedback gathering
3. **Refinement**: Proposal refinement based on feedback
4. **Consensus Building**: Attempt to reach agreement among stakeholders
5. **Decision**: Final decision by maintainers if consensus cannot be reached

### 📊 Types of Decisions

#### 🔧 Technical Decisions
**Examples**: API changes, architecture decisions, technology choices
**Process**: RFC (Request for Comments) process for major changes
**Decision Makers**: Maintainers with input from active contributors and community

#### 📋 Process Decisions
**Examples**: Governance changes, contributor guidelines, release processes
**Process**: Community discussion followed by maintainer consensus
**Decision Makers**: Maintainers with community input

#### 🚀 Strategic Decisions
**Examples**: Project roadmap, partnerships, major initiatives
**Process**: Community input, maintainer discussion, project lead approval
**Decision Makers**: Project lead with maintainer consensus

### ⚖️ Conflict Resolution

When disagreements arise:

1. **Direct Discussion**: Encourage parties to resolve disagreements directly
2. **Mediation**: Maintainers mediate discussions when needed
3. **Community Input**: Seek broader community perspective
4. **Maintainer Decision**: Maintainers make final decision if needed
5. **Project Lead Override**: Project lead has final authority in unresolvable conflicts

## 📝 RFC Process

For major technical changes, we use an RFC (Request for Comments) process:

### 📋 When to Use RFC
- Breaking API changes
- Major architectural changes
- New core features
- Significant process changes

### 🔄 RFC Process
1. **Draft RFC**: Create RFC document using template
2. **Submit**: Create pull request to `rfcs/` directory
3. **Discussion**: Community discussion period (minimum 2 weeks)
4. **Revision**: Update RFC based on feedback
5. **Final Comment Period**: 1 week final comment period
6. **Decision**: Maintainers accept, reject, or postpone RFC
7. **Implementation**: If accepted, implementation can begin

### 📄 RFC Template
```markdown
# RFC: [Title]

## Summary
Brief description of the proposal

## Motivation
Why is this change needed?

## Detailed Design
Technical details of the implementation

## Alternatives Considered
What other approaches were considered?

## Open Questions
What questions remain?
```

## 📊 Meetings and Communication

### 🗓️ Regular Meetings

**Community Calls**
- **Frequency**: Monthly, first Wednesday at 3 PM UTC
- **Purpose**: Project updates, community Q&A, feature discussions
- **Participants**: Open to all community members
- **Format**: Video call with recorded sessions

**Maintainer Meetings**
- **Frequency**: Bi-weekly, Thursdays at 2 PM UTC
- **Purpose**: Technical decisions, planning, issue resolution
- **Participants**: Maintainers and active contributors
- **Format**: Private video call with published minutes

**Design Reviews**
- **Frequency**: As needed for major features
- **Purpose**: Technical design review and approval
- **Participants**: Relevant maintainers and contributors
- **Format**: Video call or asynchronous written review

### 💬 Communication Channels

**Asynchronous Communication**
- 🐛 **GitHub Issues**: Bug reports, feature requests, support
- 💭 **GitHub Discussions**: General discussion, Q&A, announcements
- 📝 **GitHub PRs**: Code review and technical discussion
- 📧 **Email**: [governance@algorand-mcp.com](mailto:governance@algorand-mcp.com)

**Synchronous Communication**
- 📹 **Community Calls**: Monthly video meetings
- 💬 **Discord** (coming soon): Real-time chat and support
- 📞 **Ad-hoc Calls**: Scheduled as needed for specific topics

## ⚖️ Code of Conduct Enforcement

### 📋 Enforcement Team

**Code of Conduct Committee**:
- 2-3 maintainers
- 1 community representative
- External advisor (if needed)

**Responsibilities**:
- Investigate reported violations
- Determine appropriate responses
- Implement enforcement actions
- Maintain confidentiality
- Document patterns and improvements

### 🔄 Enforcement Process

1. **Report**: Violation reported to [conduct@algorand-mcp.com](mailto:conduct@algorand-mcp.com)
2. **Acknowledge**: Response within 24 hours
3. **Investigate**: Gather information and evidence
4. **Decide**: Determine appropriate action
5. **Implement**: Apply enforcement measures
6. **Follow-up**: Monitor and document outcomes
